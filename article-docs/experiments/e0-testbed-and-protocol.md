# E0 — Shared testbed, factorial design and protocol

Status: **planned, not run.** Written 2026-11-10 to aim the paper at a Strong Accept under the
`VIRTUAL-REVIEWERS.md` rules (only S3/S4 findings). Every number in E1–E4 is a placeholder until
a script in this project produces it.

## Why the paper needs this
A qualitative comparison of MBD, Agile and CI/CD is the kind of paper R1 (hostile expert) rejects
for K03 (novelty asserted, not shown) and K05 (framework without evidence). The fix is a
**controlled experiment** in which each method is a factor that can be switched on and off, with
**known ground-truth defects**, so that every claim in the abstract maps to a measured effect.

## Research questions
- **RQ1 (MBD axis):** which verification stage (MIL, SIL, PIL) detects which defect class, at what
  cost in pipeline time? → E1, claim [[claims/c3-stage-detection]]
- **RQ2 (Agile + CI axis):** how does integration cadence (change batch size) change feedback
  latency, defect localisation effort and escape rate? → E2, claim [[claims/c1-integration-gain]]
- **RQ3 (CI/CD + standards):** how much of the ISO 26262 / ISO 21434 evidence per release can the
  pipeline produce without manual steps? → E3, claim [[claims/c2-standards-traceability]]
- **RQ4 (CD/OTA, optional):** does a canary stage on a replayed fleet catch regressions that escaped
  the earlier stages, and at what exposure? → E4

## Factorial design (the core of the paper)
| Factor | Levels | Method it operationalises |
|---|---|---|
| A. Verification stages | unit only · +MIL · +MIL+SIL · +MIL+SIL+PIL | MBD |
| B. Integration cadence | per increment (batch 1) · per sprint (batch k) · big-bang (all increments) | Agile |
| C. Trigger | per commit, automated · gated manual release (simulated delay) | CI/CD |

Full factorial is 4 × 3 × 2 = 24 configurations, each replayed over the same backlog and the same
injected defects, so comparisons are **paired**.

## Protocol rules (to pass M04, M05, M06, M11)
1. Commit this protocol, the mutation operators and the analysis script **before** any run, with a
   timestamp (needs `git init`, t-0014). Anything decided after seeing data is labelled exploratory.
2. Each configuration × subject is replayed R ≥ 10 times for time metrics (runner noise).
3. Detection rates: Wilson 95 % CI; paired configuration comparisons on the same mutants: McNemar.
   Times: median, IQR, bootstrap 95 % CI; effect size Cliff's delta.
4. Equivalent mutants are screened (no output change on any input) and reported, not silently dropped.
5. A perfect detection or zero escape triggers an M11 audit before it stays in the paper.

## Threats to validity to discuss (not to hide)
- Injected mutants are a proxy for real defects; justify with mutation-testing literature (cite only
  after verification) and report per defect class.
- Agile is reduced to cadence and batch size; team practices (ceremonies, collaboration) are **not**
  measured. The title and abstract must say this (K06).
- PIL on a remote MCU is not HIL: no plant I/O, no real-time loop closure. Called PIL in the paper.
- Pipeline times depend on the runner; reported with hardware spec and repeated runs.
- Two subjects, both energy/powertrain estimators; ADAS perception is out of scope.

## Decisions
- **[#d-0003]** date: 2026-11-10 · status: proposed · author: osvaldo
  **Operationalise "Agile" as integration cadence / change batch size, not as team practice.**
  Why: it is the only Agile property measurable without a human team in five weeks. Rejected a
  survey or team study (no time, ethics approval). Cost: a reviewer can say Agile is reduced to a
  parameter; the paper must state it (K06, M08).
- **[#d-0004]** date: 2026-11-10 · status: proposed · author: osvaldo
  **Open toolchain (OpenModelica + FMI + gcc + FIT IoT-LAB) instead of MATLAB/Simulink.**
  Why: reproducible by any reviewer (X domain), no licence. Rejected Simulink as primary because no
  licence is confirmed here. Cost: industrial reviewers may see it as less representative; mention
  that the same stages exist in Simulink/TargetLink flows.
- **[#d-0005]** date: 2026-11-10 · status: proposed · author: osvaldo
  **Ground truth by mutation injection, with classes and equivalent-mutant screening.**
  Why: without known defects, detection and escape cannot be measured. Rejected mining real defect
  histories (no access to industrial repositories). Cost: validity of mutants as real-defect proxy.
- **[#d-0006]** date: 2026-11-10 · status: proposed · author: osvaldo
  **The real-MCU stage is named PIL, never HIL; VIL is out of scope.**
  Why: no plant I/O or vehicle; calling it HIL is an S1 overclaim. Cost: the four-stage figure
  (MIL/SIL/HIL/VIL) from the infographics cannot be reproduced as is.
